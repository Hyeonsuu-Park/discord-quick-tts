# 보안에 관련된 행동은 입력 어댑터에서 감사 로그 한 줄로 남긴다

- 상태: 채택
- 날짜: 2026-11-28

모르는 사람에게 데스크톱 앱을 나눠 주면 "이 기기는 언제 누가 연결했나", "허용 목록은 누가 바꿨나", "누가 몰아 보냈나" 를 물을 일이 생깁니다. 지금까지는 이런 일을 남기는 곳이 없었고, 허용 목록에 없는 서버에서 나갈 때만 일반 로그 한 줄이 있었습니다. 장애 때 할 일을 적은 곳도 없었습니다.

## 결정

1. **감사 로그는 로거 `quicktts.audit` 에 `audit event=<사건> <키>=<값> ...` 한 줄로 남깁니다(`shared/adapter/in/AuditLog`).** `grep "audit event="` 하나로 모아 보고, 같은 키와 값을 SLF4J 키-값으로도 붙여서 나중에 JSON 로그로 바꾸면 그대로 필드가 됩니다.
2. **남기는 자리는 행동을 받은 입력 어댑터입니다.** 누가(디스코드 사용자, IP) 무엇을 해서 어떻게 됐는지가 모두 보이는 곳이 디스코드 명령과 웹 요청을 받는 곳입니다. 유스케이스와 도메인은 감사 로그를 모릅니다. 봇이 서버에서 나가는 일만 출력 어댑터에서 남깁니다.
3. **사건**: 연결 코드 받기, 기기 등록과 거절, 기기 해제, 틀린 기기 토큰, 사용량 제한, 허용 목록 추가·삭제와 거절, 허용되지 않은 서버에서 나가기. 목록은 `docs/runbook.md` 에 둡니다.
4. **비밀은 남기지 않습니다.** 기기 토큰과 연결 코드는 쓰지 않고, 등록한 기기는 DB 에 저장된 토큰 해시의 앞 12자로 가리킵니다. 사용량 제한은 몰아 보내는 동안 줄이 쌓이지 않게 같은 키를 1분에 한 줄만 남깁니다.
5. **운영 안내서 `docs/runbook.md` 를 둡니다.** 알림마다 할 일(ADR 0074), DB 되살리기(ADR 0073), 새 판 올리기와 되돌리기, 감사 로그 보기, 몰아 보낼 때, 비밀이 새었을 때, 서버 주소가 바뀌었을 때를 위에서부터 따라 할 수 있게 적습니다.

## 결과

- 기기 등록, 허용 목록 변경, 남용을 나중에 되짚을 수 있습니다.
- 디스코드 사용자 ID 와 IP 가 로그에 남습니다. 이 PC 배포는 컨테이너 로그를 30MB 까지만 남기므로 오래 쌓이지 않습니다. 서비스를 공개할 때 개인정보 안내에 적습니다.
- 감사 로그가 일반 로그와 같은 곳에 섞여 있어서 30MB 를 넘으면 함께 지워집니다. 오래 남겨야 하면 로그 모으는 곳(Loki 등)을 둘 때 `quicktts.audit` 만 따로 오래 남깁니다.

## 고르지 않은 것

- 감사 기록을 DB 표에 쓰기: 표와 정리 작업이 하나씩 늘고, 지금 묻는 질문은 로그 검색으로 답할 수 있습니다.
- 유스케이스 안에서 남기기: 웹 요청의 IP 같은 입력 쪽 정보가 없고, 감사용 출력 포트가 유스케이스마다 늘어납니다.
- 스프링 이벤트나 AOP 로 모아 남기기: 무엇이 남는지 코드에서 바로 보이지 않습니다.
