# 쿠버네티스 매니페스트는 deploy/k8s 에 Kustomize 로 두고, 봇 서버는 한 벌만 띄운다

- 상태: 채택
- 날짜: 2026-11-23

봇 서버 이미지가 ghcr.io 에 올라가게 되었습니다(ADR 0058). 이제 클러스터에 무엇을 어떻게 띄울지 적어 둘 곳이 필요합니다. 띄울 곳은 둘입니다. 현수 PC 의 k3d 클러스터(개발)와 나중의 배포 서버입니다. 둘은 이미지 태그, 비밀값, 바깥에 내보내는 방법만 다릅니다.

봇 서버는 보통 웹 서버와 다릅니다. 디스코드 게이트웨이 연결, 길드마다 음성 연결과 재생 순서, 음성 채널 상태가 모두 파드 메모리에 있습니다. 같은 봇 토큰으로 두 벌이 붙으면 디스코드가 이벤트를 두 벌에 다 보내서 명령이 두 번 처리되고, 음성 연결은 나중에 붙은 쪽이 앞의 것을 끊습니다.

## 결정

1. **매니페스트는 저장소의 `deploy/k8s/` 한 곳에 둡니다.** 코드와 배포를 한 사람이 같이 바꾸므로 같은 PR 에서 고칩니다. 팀이 생겨 권한을 나눠야 하면 이 폴더를 배포 전용 저장소로 옮깁니다.
2. **Kustomize 의 base 와 overlays 로 나눕니다.**
   - `base/`: 모든 환경이 같이 쓰는 것. `bot-server/`, `mysql/`, 네임스페이스 `quicktts`.
   - `components/`: 환경에 따라 넣고 빼는 것. 지금은 `cloudflared/`(Cloudflare Tunnel) 하나.
   - `overlays/local`, `overlays/prod`: 이미지 태그, 비밀값, 켜는 component.
   - 서비스가 늘면 `base/<서비스>/` 를 더합니다. 폴더 이름은 `apps/<서비스>` 와 같습니다.
   - 우리가 만든 것은 Kustomize, 남이 만든 것(모니터링 등)은 그쪽이 내는 Helm 차트에 값 파일만 둡니다.
3. **봇 서버는 `replicas: 1`, 배포 전략은 `Recreate` 입니다.** 새 파드를 띄우기 전에 옛 파드를 내려서, 업데이트 때 잠깐(재시작 시간만큼) 끊기는 대신 두 벌이 겹치지 않게 합니다. 자동으로 늘리기(HPA)도 붙이지 않습니다. 여러 벌이 필요해지면 샤드를 나눠 맡기는 방식으로 따로 정합니다.
4. **프로브는 관리 포트(8081)를 씁니다(ADR 0057).** 시작 프로브는 디스코드 연결과 DB 마이그레이션까지 2분 30초 기다리고, 살아 있음(liveness)은 JVM 만, 준비됨(readiness)은 디스코드와 DB 까지 봅니다. 디스코드가 끊기면 요청만 받지 않고 재시작하지 않습니다. JDA 가 스스로 다시 붙기 때문입니다.
5. **비밀값은 커밋하지 않습니다.** 오버레이 폴더의 `*.env.example` 을 `.example` 을 뗀 이름으로 복사해 채우면 Kustomize 가 Secret 을 만듭니다. 디스코드 토큰(`bot-server-secrets`)과 DB 비밀번호(`mysql-secrets`)는 따로 두어, 봇 서버에는 MySQL root 비밀번호가 들어가지 않습니다. 채운 파일은 `.gitignore` 에 있습니다. 비밀이 아닌 설정은 ConfigMap 으로 만들고, 값이 바뀌면 이름 해시가 바뀌어 파드가 다시 뜹니다.
6. **컨테이너는 root 가 아니고, 루트 파일 시스템은 읽기 전용입니다.** 쓰는 곳은 `/tmp`(빈 볼륨) 하나입니다. 쿠버네티스의 `restricted` 보안 기준을 따릅니다.
7. **MySQL 은 클러스터 안 StatefulSet 하나로 시작합니다.** 클라우드의 관리형 MySQL 을 쓰게 되면 `base/mysql` 을 빼고 `QUICKTTS_DB_URL` 만 바꿉니다.
8. **바깥에서 들어오는 길은 Cloudflare Tunnel 하나입니다(prod).** 공인 IP 나 Ingress 컨트롤러, 인증서 없이 웹 API(8080)만 내보냅니다. 관리 포트는 내보내지 않습니다. 개발(local)은 `kubectl port-forward` 를 씁니다.
9. **CI 가 오버레이마다 펼쳐 스키마를 검사합니다.** 클러스터 없이 매니페스트 오타와 필드 이름 실수를 PR 에서 잡습니다.

## 결과

- 처음 띄우려면 클러스터(k3d)와 개발용 디스코드 봇 토큰이 필요합니다. 배포 봇과 같은 토큰을 쓰면 위의 두 벌 문제가 생깁니다.
- ghcr.io 이미지가 비공개면 클러스터가 받지 못합니다. 패키지를 공개로 바꾸거나 `imagePullSecrets` 를 더합니다.
- `prod` 오버레이의 이미지 태그는 지금 `main` 입니다. 실제로 배포할 때 버전이나 `main-<커밋>` 으로 고정합니다.

## 고르지 않은 것

- Helm 차트로 직접 만들기: 템플릿 문법을 익혀야 하고, 우리 서비스 하나를 위해 값 파일을 하나 더 둬야 합니다. 남에게 배포판을 나눠 줄 일이 생기면 그때 만듭니다.
- 서비스 폴더마다 `k8s/` 두기: 환경마다 다른 값이 서비스 수만큼 흩어집니다.
- 봇 서버 두 벌 이상과 롤링 업데이트: 위의 두 벌 문제 때문에 지금 구조로는 할 수 없습니다.
- Sealed Secrets, External Secrets: 클러스터가 하나이고 사람도 한 명이라 아직 얻는 것이 작습니다. GitOps(Argo CD)를 들일 때 같이 정합니다.
