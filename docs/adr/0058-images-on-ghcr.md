# 서버 이미지는 GitHub Actions 가 만들어 ghcr.io 에 올린다

- 상태: 채택
- 날짜: 2026-11-23

봇 서버 이미지는 Dockerfile 로 만들 수 있지만(ADR 0055) 만드는 사람 PC 에만 있었습니다. 쿠버네티스는 레지스트리에서 이미지를 받으므로, 누가 어디서 배포하든 같은 이미지를 받을 곳과 이름 짓는 규칙이 있어야 합니다. 설치 파일은 이미 `v*` 태그로 GitHub Releases 에 올라갑니다(ADR 0020).

## 결정

1. **레지스트리는 GitHub Container Registry(`ghcr.io`)입니다.** 저장소와 같은 곳에 있고, 워크플로의 `GITHUB_TOKEN` 으로 올려서 비밀값을 따로 두지 않습니다.
2. **이미지 이름은 `ghcr.io/phs314/quicktts-<서비스>` 입니다.** 서비스 이름은 `apps/` 아래 폴더 이름과 같습니다(지금은 `bot-server`).
3. **태그는 세 가지입니다.**
   - `v1.2.3` 태그: `:1.2.3`, `:1.2`. 설치 파일 Release 와 같은 버전입니다.
   - main 머지: `:main`(늘 최신 main), `:main-<커밋 7자리>`(되돌릴 때 고르는 고정 태그).
   - `latest` 는 쓰지 않습니다. 무엇이 들어 있는지 이름으로 알 수 없어서입니다.
4. **워크플로는 `.github/workflows/images.yml` 하나이고, 서비스는 matrix 로 늘립니다.** PR 에서는 만들기만 하고 올리지 않습니다. amd64 와 arm64 를 함께 만듭니다.
5. **빌드 캐시는 GitHub Actions 캐시(`type=gha`)에 둡니다.** Gradle 의존성 레이어가 남아 코드만 바뀐 빌드가 짧습니다.

## 결과

- 쿠버네티스 매니페스트는 운영(prod)에서 `:1.2.3` 이나 `:main-<커밋>` 처럼 고정 태그를 적고, 로컬 클러스터는 `:main` 을 씁니다.
- ghcr.io 에 처음 올린 이미지는 비공개입니다. 클러스터가 토큰 없이 받게 하려면 GitHub 의 패키지 설정에서 공개로 바꾸거나, 클러스터에 이미지 받기용 비밀값(`imagePullSecrets`)을 둡니다.
- Dependabot 이 Dockerfile 의 베이스 이미지와 개발용 `compose.yaml` 의 MySQL 새 버전도 알립니다.
- `.github/CODEOWNERS` 로 모든 폴더의 리뷰어를 현수로 둡니다. 사람이 늘면 폴더마다 나눕니다.

## 고르지 않은 것

- Docker Hub: 무료 계정은 받기 횟수 제한이 있고, 올리려면 비밀값을 따로 둬야 합니다.
- 클라우드 레지스트리(Oracle OCIR, AWS ECR 등): 배포할 클라우드가 아직 정해지지 않았습니다. 정해지면 그쪽으로 함께 올리면 됩니다.
- 서비스마다 워크플로 파일: 서비스가 늘 때마다 같은 내용을 복사하게 됩니다.
