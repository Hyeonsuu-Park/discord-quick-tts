# 시간 제한은 안쪽일수록 짧게 두고, TTS 엔진마다 차단기를 둔다

- 상태: 채택
- 날짜: 2026-11-28

quick chat 한 번은 데스크톱 앱 → 봇 서버 → synthesis 서비스 → TTS 엔진(Edge, 실패하면 Google)을 지납니다. 지금까지 시간 제한이 바깥일수록 짧았습니다. 앱은 10초, 봇 서버는 synthesis 를 45초까지 기다렸고, synthesis 안에서 Edge 는 연결 15초와 응답 15초를 따로 기다린 뒤 Google 로 10초를 더 썼습니다.

그래서 Edge 가 느린 날에는 앱이 10초에 실패를 보여 준 뒤에도 서버는 계속 만들어서 30~40초 뒤에 읽었습니다. 사용자가 다시 보내면 두 번 읽히고, 다시 보낸 문장이 캐시에 있으면 앞 문장보다 먼저 읽혔습니다. Edge 가 막힌 날에는 모든 요청이 매번 15~30초를 기다린 뒤에야 Google 로 넘어갔고, 그동안 요청 스레드를 쥐고 있었습니다. ADR 0062 는 차단기를 "느려지는 게 지표에 보이면 그때" 더하기로 했지만, 앱 쪽 결과가 이미 틀리므로 지표를 기다릴 일이 아닙니다.

## 결정

1. **시간 제한은 안쪽으로 갈수록 짧게 둡니다.** 안쪽이 먼저 끝나야 바깥이 받은 결과와 실제로 일어난 일이 같습니다.

   | 구간 | 시간 제한 | 설정 |
   | --- | --- | --- |
   | Edge 한 번(연결부터 마지막 음성 조각까지) | 4초 | `quicktts.tts.edge-timeout` |
   | Google 번역 한 번(연결부터 본문까지) | 3초 | `quicktts.tts.google-timeout` |
   | synthesis 서비스 한 번 | 최대 7초(Edge 4초 + 대신 읽기 3초) | 위 둘의 합 |
   | 봇 서버 → synthesis | 연결 1초, 응답 8초 | `spring.http.serviceclient.synthesis.*` |
   | 데스크톱 앱 → 봇 서버 | 10초 | `QuickTtsClient` |

   Edge 는 연결, 보내기, 받기에 시간을 따로 주지 않고 마감 시각 하나를 나눠 씁니다. Google 은 요청의 `timeout` 이 응답 머리까지만 재므로 본문까지 받는 시간을 한 번 더 자릅니다.
2. **TTS 엔진마다 차단기(Resilience4j `CircuitBreaker`)를 둡니다.** 최근 10번 중 절반 넘게(5번부터 셈) 실패하면 30초 동안 그 엔진을 부르지 않고 바로 실패합니다. Edge 가 막히면 기다리지 않고 곧바로 Google 로 읽습니다. 30초 뒤 두 번 시험 삼아 불러서 되면 다시 엽니다.
3. **차단기는 엔진 안, 캐시 안쪽에 둡니다.** 캐시에서 꺼낸 음성을 성공으로 세면 Edge 가 막혀도 차단기가 열리지 않습니다. 엔진은 `TtsEngine.throughCircuitBreaker` 로 바깥 호출을 감싸고, 열린 차단기는 `SpeechSynthesisException` 으로 바꿔서 대신 읽기(`SpeechSynthesizerAdapter`)가 지금처럼 동작합니다.
4. **차단기 상태는 `resilience4j.circuitbreaker.state` 지표로 냅니다.** `name` 태그가 엔진 이름(`edge`, `google`)입니다. 알림 규칙은 이 지표를 봅니다.
5. **봇 서버 → synthesis 에는 차단기를 두지 않습니다.** 서비스가 죽으면 연결이 바로 거절되어(1초 안) 기다리는 일이 없고, 느린 경우는 안쪽 엔진 차단기가 먼저 막습니다. 다시 시도하지 않음(ADR 0062 결정 6)도 그대로입니다.

## 결과

- 앱이 실패를 보여 준 문장은 서버에서도 실패한 문장입니다. 늦게 읽히거나 두 번 읽히지 않습니다.
- Edge 가 잠깐 느릴 때(4초 넘게) Google 목소리로 읽히는 일이 늘어납니다. 200자 문장도 Edge 는 보통 1~2초 안에 보냅니다.
- 의존성이 둘(`resilience4j-circuitbreaker`, `resilience4j-micrometer`) 늡니다. 스프링 부트 시작 묶음 대신 핵심 라이브러리만 씁니다.
- 시간 제한을 바꿀 때는 위 표의 순서를 지킵니다.

## 고르지 않은 것

- Resilience4j 스프링 부트 시작 묶음(`@CircuitBreaker` 애너테이션): 엔진 둘에 한 줄씩이라 애너테이션과 프록시가 더 복잡합니다. 설정을 `application.yml` 로 빼는 것도 지금은 필요 없습니다.
- 차단기를 `SpeechSynthesizerAdapter` 에 두기: 캐시 바깥이라 캐시에서 꺼낸 것도 성공으로 셉니다(결정 3).
- 시간 제한을 늘려 앱을 45초 넘게 기다리게 하기: 한 문장에 몇십 초를 기다리는 단축키는 쓸 수 없습니다.
