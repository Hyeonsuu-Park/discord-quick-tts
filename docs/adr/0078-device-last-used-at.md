# 기기마다 마지막으로 쓴 시각을 한 시간 단위로 남긴다

- 상태: 채택
- 날짜: 2026-11-28

기기 토큰에는 만료도 마지막 사용 시각도 없어서, 바꾼 PC, 팔아 버린 노트북, 한 번 깔아 보고 지운 PC 의 토큰이 계속 살아 있습니다. 사용자도 운영자도 어느 것이 오래 안 쓴 기기인지 알 수 없었습니다.

## 결정

1. **`device.last_used_at` 열을 더합니다(V6).** null 을 허용하는 늘리기만 하는 마이그레이션이라 앞 판 서버도 그대로 돕니다(ADR 0073). 이 열이 생기기 전에 등록했거나 아직 안 쓴 기기는 null 입니다.
2. **기기 토큰을 인증할 때 적되, 한 시간에 한 번만 적습니다.** 요청마다 쓰면 quick chat 한 번에 DB 쓰기가 하나 늡니다. 적을 때는 엔티티를 읽지 않고 `update ... set last_used_at` 한 문장으로 고칩니다. 그래서 값은 한 시간까지 늦을 수 있습니다.
3. **`/연결해제` 메뉴에 등록 시각과 마지막 사용 날짜(한국 시각)를 함께 보여 줍니다.** 오래 안 쓴 PC 를 사용자가 골라 끊습니다. 운영자는 DB 에서 `last_used_at` 으로 찾습니다(`docs/runbook.md`).
4. **오래 안 쓴 기기를 저절로 끊지는 아직 않습니다.** 며칠을 기준으로 할지는 쓰는 사람이 늘고 사용 기록이 쌓인 뒤 정합니다.

## 결과

- 기기마다 대략 언제까지 썼는지 알 수 있습니다.
- 인증은 조회인데 한 시간에 한 번 쓰기가 붙습니다. 토큰을 쓰는 서비스에서 흔히 하는 방식이고, 쓰기는 인증 서비스 한 곳에만 있습니다.

## 고르지 않은 것

- 요청마다 적기: 정확하지만 quick chat 마다 DB 쓰기가 늡니다.
- 메모리에 모았다가 몇 분마다 한꺼번에 적기: 더 적게 쓰지만 서버가 꺼질 때 잃는 값과 정리 작업이 생기고, 한 시간 단위면 충분합니다.
- 토큰에 만료일 두기: 만료될 때마다 사용자가 `/연결` 을 다시 해야 합니다. 먼저 사용 기록을 보고 정합니다.
